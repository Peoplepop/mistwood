# 第六階段：怪物同步（Cloudflare Durable Objects）

## 架構

```
瀏覽器 ──HTTPS──▶ PythonAnywhere（帳號、雲端存檔、排行榜，不動）
   │                    │ 登入後簽發短效「連線票券」（HMAC，約 5 分鐘）
   └──WebSocket──▶ Cloudflare Worker ──▶ Durable Object「頻道 1～10」
                                          每頻道一份：怪物、玩家位置、聊天
```

- 每個頻道一個 Durable Object（`idFromName('ch-N')`），10～20 Hz 模擬怪物；沒人時停止 tick、休眠。
- **怪物由伺服器權威**：出生、HP、位置、AI、死亡、重生。只模擬有玩家所在區域的怪。
- **玩家由客戶端權威**：移動、技能、自身 HP（被怪打的傷害在前端依伺服器怪物位置判定）。每秒約 10 次回報位置。
- **打怪**：前端判定命中與傷害並立即顯示；送 `hit` 給伺服器，伺服器檢查（怪還活著、距離、傷害上限依票券中的等級/職業、出手頻率）後扣血。
- **興趣範圍**：每人只收左右約 1500px 內的怪物快照。
- **備援**：連不上 Worker 時，自動退回單機本地怪 + 現有 HTTP 輪詢。
- **共用程式碼**：`index.html` 仍是唯一來源（Artifact 需要單一檔案）；怪物資料與 AI 用標記區塊包起來，`worker/` 的同步腳本把它抽出成 Worker 用的模組。

## 已決定的規則（2026-10-13 使用者確認）

1. **訪客**：不連同步頻道，打本機單機怪，**也看不到其他玩家**（登入後才看得到）。這會取代目前「訪客唯讀看得到其他玩家」的行為。
2. **經驗分配**：依傷害比例分，最後一擊另加一點；任務擊殺數給有出力的人。
3. **掉寶**：個人掉寶，每位有出力的玩家在自己的前端各自擲骰，只看得到自己的掉落。

### 6-2 部署步驟（使用者）

GitHub Pages 上的新前端在 Worker 更新前會繼續使用本機怪物（舊 Worker 的 welcome 沒有 `mobs`），所以前端先上線沒有問題。

```bash
cd worker
git pull
npm install
npm test                 # 19 項通過
npx wrangler deploy      # npm run deploy 也可以（會先檢查 mobs.gen.js 是否最新）
```

部署後登入遊戲，社群視窗（C）顯示「連線方式：即時連線（WebSocket，怪物同步）」就是成功了；可以兩個帳號一起打同一隻怪確認經驗分配。
緊急關閉：把 `worker/src/channel.js` 的 `MOB_SYNC` 改成 `false` 再部署（前端自動改回本機怪物）。

6-3（Boss 同步）的部署步驟相同：`npm test`（37 項）→ `npx wrangler deploy`。部署後在祭壇附近，血條出現「N 人共鬥」（兩人以上時）就是伺服器的 Boss。
緊急關閉 Boss 同步（一般怪照常）：把 `worker/src/channel.js` 的 `BOSS_SYNC` 改成 `false` 再部署。

**之後修改怪物資料或 AI（`<mobsim>` 區塊）時**：在 `worker` 執行 `npm run gen`，commit 產生的 `src/mobs.gen.js`，並重新部署 Worker。
在 Worker 重新部署前，前端會因為怪物資料指紋不同而自動改用本機怪物（不會壞掉，只是暫時沒有怪物同步）。
改 Boss 的 AI 時記得把 `BOSS.ver` +1（AI 程式碼不在指紋裡），Worker 部署前 Boss 會自動改回本機。
