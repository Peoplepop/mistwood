# 第七階段：組隊系統（規劃）

> 狀態：**規劃已確認（2026-10-15）**，14 項待確認事項已由使用者裁示（見文末「已決定事項」）。
> **7-0 隊伍核心已完成（2026-10-15，本機驗證通過，Worker 尚未部署）**；部署步驟見文末「7-0 部署」。7-1～7-3 尚未開始。
> 沿用第六階段架構：PA（帳號／存檔／票券）＋ Cloudflare Worker（`Channel` DO 每頻道一個、全域 `Lobby`）。

## 架構

```
瀏覽器 ──WebSocket──▶ Channel DO（ch-1～ch-10）── RPC ──▶ PartyHub DO（全域一個，新增）
   ▲                     │  經驗共享在這裡算（只看同頻道玩家）     │ 隊伍、成員位置（頻道／地圖）、邀請
   └──── {t:'pu'/'pi'/'pe'/'pc'} ◀── partyPush(RPC) ◀──────────┘ 推給隊員所在的各頻道
```

- **隊伍狀態放新的 `PartyHub` DO**（`idFromName('hub')`，全域一個）：隊伍可跨頻道，必須有單一權威；不放 `Lobby` 是為了隔離（`Lobby.pick()` 是連線入口，隊伍程式出錯不該影響進頻道）。最多 200 人同時在線，單一 DO 綽綽有餘。
- **玩家只連自己的 Channel**：隊伍指令由 Channel 轉給 Hub（RPC）；Hub 有變化時呼叫隊員所在頻道的 `Channel.partyPush([[uid, conn, 訊息], ...])`，由 Channel 送給玩家（`conn` 不符就不送），並更新本地快取 `P.pid`／`P.pm`（隊員 uid）。
- **擊殺結算不經過 Hub**：Channel 用本地快取的隊伍成員＋本頻道玩家位置算經驗共享（隊友不在同頻道就不可能符合條件），打怪路徑沒有額外延遲。
- **隊友 HP／位置**：同頻道已經有 `{t:'ps'}`（含 `hp`、`x`）→ 前端直接從 `NET.others` 取；Hub 只記 `ch`、`z`（0 = 森林、1 = 雪原，依 `zoneL`）、`lv`、`job`、在線與否，給跨頻道的隊伍視窗顯示。
- 純邏輯放可單獨測試的模組（比照 `mobworld.js`）：`src/party.js`（`PartyBook`：隊伍／邀請規則，不依賴 Cloudflare）、`src/share.js`（`splitPartyExp`，7-2）。

## 已決定的規則（使用者確認）

1. 隊伍上限 **4 人**；只有登入且走 WebSocket 的玩家能組隊（訪客、HTTP 備援不行）。
2. **經驗共享＋加成**：怪物死亡時，同頻道、同地圖、約 1 個畫面內的隊友，沒打也分得到；隊內依等級比例分；每多 1 位符合條件的隊友，隊伍總經驗 +10%。
3. **可跨頻道**：換頻道不退隊；隊伍視窗顯示隊友頻道／地圖；只有同頻道同地圖才分經驗、看得到 HP。
4. 附加功能：隊伍聊天、小地圖標示隊友、隊長踢人／轉移隊長、隊伍 Boss 額外掉寶（7-3）。**不做隊伍任務**（q15 與任務類型 `pkill` 取消）。
5. 基本功能：邀請（玩家資訊卡、社群視窗）、接受／拒絕（**邀請不逾時**）、退出、隊伍 HP 條 UI（含手機）。
6. **任何隊員都能邀請**（不限隊長）；**離線不自動退隊、隊長離線不自動轉移**（詳見「隊伍規則」）。

## 經驗共享規則（7-2）

**流程**（取代 `MobWorld.hit()` 擊殺後直接用 `splitExp` 結果）：
1. 照舊 `splitExp(exp, m.dmg, last)`：依傷害比例、多人最後一擊 +10%，總和 = 怪物經驗。
2. **不在隊伍的出力者**：拿自己那份，和現在完全一樣。
3. **每個有出力者的隊伍**：隊伍份額 `pool` = 隊內出力者份額總和；符合條件隊友 `E`（含出力者本人）；
   `total = round(pool × (1 + 0.1 × (|E| − 1)))`，依 `lv_i / Σlv` 分（無條件捨去，零頭給隊內最後一擊或出力最多者）。
4. 隊伍裡沒人出手 → 不分（避免旁觀灌經驗）。

**符合條件的隊友**（沒出手的人；出力者本人一律算）：
- 同頻道、同地圖（`zoneL` 相同）、與怪物距離 `|dx| ≤ PARTY_SHARE_X = 1000`、`|dy| ≤ 600`（以怪物位置為準）
- 活著（`st !== 'dead'`）、最近 `PARTY_ACTIVE_MS = 30 秒` 內有回報狀態（防掛機）
- 前端支援組隊（hello 帶 `pty`）
- **等級差**：等級 ≥ 符合條件者中最高等級 − `PARTY_LV_GAP`（`= 15`；低太多的人不分、也不計入加成）

**上限**（讓後端不用放寬經驗常數）：
- 一般怪：每人一次 ≤ 怪物基礎經驗 `m.d.exp`（數學上只有極端等級差才會超過，Worker 仍夾住；前端 `mnKill` 本來就 `clamp(x, 0, m.d.exp)`）。
- Boss：達討伐門檻者 ≤ 9000；**沒達門檻的隊友**分到的 ≤ 2,000（＝ `MAX_EXP_PER_KILL`），算 1 次「協助擊殺」，不算 Boss 擊殺／q10／掉寶。
- 討伐門檻（`bossCredit`）仍看個人輸出，不受隊伍影響（不做隊伍門檻）。

**範例**：怪物 1000 經驗；A（隊伍、Lv.40）出 70% 且最後一擊、B（隊外）30%。`splitExp` → A 730、B 270。A 的隊友 C（Lv.36）在旁邊、D 在別張地圖 → E = {A, C}，total = 803 → A 423（含零頭）、C 380；B 照拿 270（全場 1073）。

**沒出手的隊友收到結算時**（`a = 1`）：給經驗、`stats.assists +1`、**算任務擊殺數**，**不擲掉寶**（個人掉寶規則不變）。

**對後端合理性檢查的影響**（`server/app.py`）：
- `MAX_EXP_PER_KILL`、`BOSS_EXP_MAX`、`EXP_PER_SEC_MAX` 不用改（每人每隻 ≤ 基礎經驗）。
- 問題：沒出手的隊友有經驗但沒擊殺 → `min_kills_for_level` 可能誤判「等級與擊殺數不符」。
- 做法：新增 `stats.assists`（協助擊殺數），存檔多一欄；後端 `extract_scores` 讀 `assists`，`min_kills_for_level` 用 `kills + assists`；新增 `hw_assists`／`hw_assists_ts` 欄位以 `KILLS_PER_SEC_MAX` 檢查速度；**擊殺排行榜仍只算 `kills`**（不被組隊灌）；金幣檢查不變（協助擊殺沒有金幣）。
- 風險：4 人隊狂掃時每人 `kills + assists` 成長 = 全隊擊殺速度，可能逼近 `KILLS_PER_SEC_MAX = 5`（寬限 300）；7-2 實測看 flag_reason，必要時調到 8。

## 隊伍規則（7-0）

- **建立**：未組隊者邀請他人、對方接受 → 建立隊伍，邀請者為隊長（邀請者當時離線也照樣建立）。
- **邀請**：**任何隊員都能邀請**（未組隊者也可以）；被邀請者需在線（WebSocket）、支援組隊、未在隊伍中，邀請者的隊伍未滿；邀請頻率限制（每人 3 秒 1 次、每分鐘 10 次）。邀請入口在同頻道（資訊卡、社群視窗），Hub 本身支援跨頻道送達。
  - **邀請不逾時**：一直有效，直到下列任一情況才結束（作廢時雙方都會收到 `pe void`，畫面上的邀請提示自動消失）：
    1. 被邀請者**接受**或**拒絕**；
    2. 邀請者的隊伍**已滿 4 人**（隊伍一滿，所有以這個隊伍名義發出的待處理邀請一律作廢）；
    3. 邀請者**已離隊**（自己退出或被踢；邀請者發出的所有待處理邀請作廢）；
    4. 被邀請者**離線**（斷線、登出、被取代暫停、退回 HTTP 備援都算）；
    5. 被邀請者**已加入其他隊伍**（例如他自己邀請的人先接受了）。
  - **邀請者離線不影響邀請**：被邀請者仍可接受，加入邀請者「接受當下」所在的隊伍（邀請者是未組隊者就新建隊伍）。
  - **每位被邀請者同時只保留一筆待處理邀請**：別人再邀請他時，新邀請**取代**舊的（舊邀請者收到 `pe void`，原因「對方收到其他邀請」）；同一位邀請者重複邀請同一人只是重新送出提示。一位邀請者可以同時邀請多人（隊伍滿時其餘的作廢）。
  - 待處理邀請存在 Hub storage：Hub 閒置被回收（正式環境約 1～2 分鐘沒有請求，本機 `wrangler dev` 約 10 秒）、重新啟動後邀請仍有效。部署新版 Worker 時所有連線會重連；沒有重連的被邀請者 2 分鐘後視為離線，邀請隨之作廢。
- **退出**：任何人隨時可退出；隊長退出 → 最早加入的**在線**隊員接任（都不在線就給最早加入的隊員）；剩 1 人 → 解散。
- **踢人／轉移隊長**：隊長限定；**可以踢離線的隊員**；轉移對象必須在線（避免把隊長交給長期不上線的人）；被踢者 60 秒內不能再被同隊邀請。
- **離線不退隊**（第 7 項不做）：隊員只會因**自己退出**或**被隊長踢出**而離隊；離線多久都還在隊伍裡，上線後自動恢復（隊伍視窗顯示「離線」）。
  - **後果**：隊長長期離線時，沒有人能踢人或轉移隊長；其他隊員仍可自行退出、仍可邀請（任何隊員都能邀請）。離線的隊員也會佔用 4 人名額，需要隊長踢出才能空出位置。
  - **剩 1 人自動解散**仍適用（退出／踢人後只剩 1 人就解散，即使剩下的人離線）。
  - **內部維護規則**（不對玩家公告）：為避免 storage 無限累積，Hub 每天用 alarm 檢查一次，**全隊所有成員 30 天都沒上線**的隊伍整隊刪除（`PARTY_PURGE_MS = 30 天`）。
- **斷線／重連**：Channel `drop()` → `hub.offline(uid, conn)`；`onHello` → `hub.online({uid, name, lv, job, ch, z, conn})`（與 welcome 同時送出，不等 Hub）。`conn` = Channel 在 hello 時產生的連線編號，Hub 只接受「目前 conn」的 offline／指令；Hub 收到 online 一律回傳目前的隊伍快照 `pu`（不在隊伍 = `null`）。
  - **換頻道**：前端先連新頻道、welcome 後才關舊連線（`rtWelcome` 的 `S.sw`）→ Hub 通常先收到新 conn 的 online、再收到舊 conn 的 offline（被忽略），隊伍不閃斷；萬一順序相反只會短暫顯示離線，最後狀態一樣。
  - **4001 被取代**：同頻道時舊連線 `drop()` 本來就不處理（`P.ws !== ws`）；跨頻道兩處連線時，Hub 以最後一個 online 為準，舊 conn 收到 `pe stale`、指令回 `stale`，前端顯示「隊伍功能在另一處使用中」。
  - **自我修復**：Channel 每 30 秒（有組隊玩家時）送 `hub.sync(ch, [在線玩家])`：Hub 不認識的在線玩家當作上線；同頻道清單裡沒有的玩家（超過 5 秒寬限）標為離線；**2 分鐘（`GHOST_MS`）沒有任何頻道確認**的「在線」玩家（所在頻道意外重啟、部署後沒有重連）視為離線，被誤判的玩家下一次 sync 或指令就恢復。
  - 登出、`/api/claim` 被取代暫停、退回 HTTP 備援 → 都算離線（不是退隊），回來自動恢復。
- **保存**：隊伍（`p:<id>`）、玩家（`u:<uid>`：隊員、在線玩家、和待處理邀請有關的玩家；名稱／等級／職業／位置／在線與 conn／最後上線時間）、邀請（`i:<被邀請者>`）都存 Hub storage（休眠／回收／部署後還在，讀回時保留在線狀態，由 sync 確認）；邀請頻率限制只放記憶體。不在隊伍、離線、也沒有待處理邀請的玩家資料會刪除。Channel 把 `conn`、`pty`、`pid`、`pm` 放進連線 attachment（≤ 2KB），醒來不必問 Hub。

## WebSocket 協定（新增）

前端 → 伺服器

| 訊息 | 說明 |
|---|---|
| `{t:'hello', ..., pty:1}` | 新欄位：前端支援組隊（沒有 = 舊版，不能被邀請、不收協助擊殺） |
| `{t:'p', q, op:'inv', id}` | 邀請 uid |
| `{t:'p', q, op:'ans', id, ok:1/0}` | 回覆邀請（id = 邀請者） |
| `{t:'p', q, op:'leave'}` / `op:'kick', id` / `op:'lead', id` | 退出／踢人／轉移隊長 |
| `{t:'p', q, op:'chat', text}` | 隊伍聊天（7-1；Channel 先跑 `prepareChat`，共用 `P.chatTs` 頻率限制） |

伺服器 → 前端（指令回覆沿用 `{t:'r', q, ok, error?}`，前端用現有 `rtRequest()`）

| 訊息 | 說明 |
|---|---|
| `welcome` 新增 `party` | 組隊協定版本（0 或沒有 = 不支援 → 前端隱藏組隊 UI） |
| `{t:'pu', p}` | 隊伍快照：`p = {id, v, lead, mem:[{id, name, lv, job, ch, z, on}]}`（`mem` 依加入順序）；`p = null` 代表不在隊伍 |
| `{t:'pi', from, name, lv, job, ch}` | 收到邀請（不逾時；新邀請取代舊的） |
| `{t:'pe', k, id, name, why?}` | 事件：`join`／`leave`／`kick`／`lead`／`decline`／`void`／`disband`／`stale`（`void` = 邀請作廢，`why`：`full` 隊伍已滿、`left` 邀請者已離隊、`off` 被邀請者離線、`party` 被邀請者已加入其他隊伍、`replaced` 對方收到其他邀請） |
| `{t:'pc', msg:{id, uid, name, text, ts}}` | 隊伍聊天（7-1） |
| `{t:'k', ..., a?, pb?, pn?, pr?}` | 擊殺結算新增：`a = 1` 協助擊殺（沒出手，只給經驗）、`pb` 隊伍加成 %、`pn` 符合條件隊友數（7-2）、`pr = 1` 隊伍討伐額外掉寶（7-3） |

Channel ↔ Hub（RPC，非 WebSocket）：`online(info)`、`offline(uid, conn)`、`loc(uid, conn, {z, lv, job})`（地圖／等級／職業有變才送）、`sync(ch, [info...])`（每 30 秒）、`cmd(info, op, args)` → `{ok, error?}`；Hub → `Channel.partyPush([[uid, conn, msg], ...])`。

## 風險與緊急開關

- **開關**（`worker/src/channel.js`，改完 `npx wrangler deploy`）：`PARTY_SYNC = false` → welcome `party: 0`，前端隱藏組隊、經驗回到純傷害比例；`PARTY_EXP = false` → 只關經驗共享；`PARTY_BOSS = false` → 只關 7-3 獎勵。
- **Hub 掛掉**：Channel RPC 失敗回 `{ok:false, error:'隊伍伺服器忙碌'}`；打怪、聊天、Boss 不受影響（共享用本地快取）。
- **競態**：換頻道／重連的 online／offline 順序 → 以 `conn` 判斷；需測試覆蓋。
- **休眠**：Hub 計時一律用 alarm；Channel 隊伍快取存 attachment；Hub 的隊伍、玩家、邀請都存 storage（閒置被回收不影響）。
- **隊長長期離線**：沒有自動轉移，無人能踢人／轉隊長；隊員可自行退出另組隊伍（玩家說明要寫清楚）。
- **濫用**：高等帶練（等級差、距離、掛機規則）、同一人多帳號帶自己（`/api/claim` 只限同帳號；IP 註冊限制有幫助但擋不完）、擊殺速度檢查誤判（看 flag_reason，必要時調 `KILLS_PER_SEC_MAX`）、邀請騷擾（頻率限制；不逾時的邀請可直接拒絕）。
- **相容**：新前端＋舊 Worker → 沒有 `party` 欄位，組隊 UI 隱藏；舊前端＋新 Worker → 沒有 `pty`，不能被邀請、不收 `a = 1`（避免舊版把協助擊殺當成擊殺並擲掉寶）。HTTP 備援、訪客一律沒有組隊。
- **用量**：隊伍指令與 online／offline／loc 都是低頻 RPC；sync 每頻道每 30 秒 1 次（只在有組隊玩家時）；位置與 HP 沿用 `ps`，Cloudflare 請求數幾乎不變。storage 寫入：每次上線／離線各 1 筆、邀請與隊伍變化各數筆。
- **單檔前端變大**：組隊 UI 集中在一段 `// ---- 組隊（第七階段） ----` 區塊，避免散落。
